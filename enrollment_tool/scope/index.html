Scope · proposed first version

AdToSeat shows which marketing campaigns actually fill school seats.

WhatConverts stays the lead-tracking foundation. AdToSeat is the connection to school outcomes. It is not a CRM and it does not replace WhatConverts.

Working in the sample

The sample dashboard is a fictional preview. Filters, charts, and the status list use built-in rows. Nothing is imported, nothing is matched to a real file, and nothing is sent to Google or Meta.

The sample chart counts inquiry, application, and enrolled. Accepted is not its own bar there.

Proposed first version

Not built. A first version would do these five things. CSV export is the honest starting point. An API is not assumed to be available.

  1. Import leads from WhatConverts and school application and enrollment outcomes from CSV exports. A live API is not part of this version. What a real export contains has to be checked before the import is trusted.
  2. Match records with a confidence indicator. Uncertain and unmatched rows wait in a review queue. The product does not guess a confirmation.
  3. Show distinct stages: inquiry, application, accepted, and enrolled, using statuses the school confirmed.
  4. Report confirmed enrollments and cost per enrollment by channel, campaign, and campus when those fields are actually in the file.
  5. Flag missing data and CSV problems so an incomplete row is not presented as a trustworthy outcome.

How a school would use it

Bring in outcomes from a CSV, or add a lead by hand when a file is not available. Review uncertain matches. View results. Brandastic manages the technical setup.

Manual entry, beside the CSV

Not built. A school needs a way to record a lead when its software does not do that automatically. Manual entry sits next to the CSV import. It is not a second admissions system, and this page does not store a real student.

  1. Add a lead.
  2. Search for an existing inquiry and link to it, so the same family is not entered twice.
  3. Update application, accepted, or enrolled by hand. Enrolled stays a different status from an accepted offer.
  4. Record who made the change and when.
  5. Require a confirmation before an enrollment is treated as confirmed.
  6. Mark a source typed by a person as manually recorded. Mark a source that arrived from WhatConverts as tracked. If the source is not known, store Unknown. Do not invent one.

Later: automatic updates from the school platform

Planned. Subject to verified API access, permissions, and platform capabilities. This is not a supported integration and it is not live.

The aim is a secure connection the school authorizes, so application and enrollment outcomes can update without uploading the same CSV again. CSV import and manual entry stay available when a connection is not possible.

  • Show whether the connection is working.
  • Show the last successful update.
  • Show a failure in plain language, with a way to retry.

The first platforms to evaluate are FACTS for Heart and Avela for CalOPS. This page does not say those connections exist, or that either school has turned them on.

How often data would move, including whether that could ever be real-time or by webhook, is not decided until access is verified. Confirmed enrollment stays distinct from an accepted offer.

Not in this version

  • No live WhatConverts, FACTS, Avela, or CalOPS connection. FACTS stays the admissions record. Avela and CalOPS setup is unknown.
  • No conversion sends to Google or Meta.
  • No ROI calculator. That stays in Google Sheets.
  • No student names or private records on this page.

A verified integration would be a later decision, after a CSV version shows whether the match is good enough. This page does not say that integration is ready.
