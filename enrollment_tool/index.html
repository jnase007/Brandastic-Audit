What the record holds

Source and campaign

Google Ads, Meta Ads, organic, and offline stay attached to the inquiry, separate from whether it arrived by call, form, or chat.

School outcome, own date

Application, accepted, and enrolled come from the school file. Each status keeps the date the school recorded.

Cost beside enrollments

Paid enrollments sit next to campaign spend. The association is visible. It is not a claim that an ad caused the seat.

How it works

  1. Connect the campaigns

    Google Ads, Meta Ads, organic, and offline stay named on the inquiry.

  2. Record the inquiry

    Call, form, or chat, with the parent or guardian, the date, and the campaign.

  3. Match the enrollment

    The school file adds application, accepted, and enrolled, each on its own date.

  4. Read the true cost

    Spend divided by enrollments tied to a paid campaign. Organic and offline stay in the count and out of that cost.

Channels stay named

Paid search stays Google Ads. Paid social stays Meta Ads. Organic and offline are their own sources. Nothing is guessed from a missing field.

  • Google AdsSearch campaigns and the click id when the lead has one.
  • Meta AdsThe Meta campaign. The record does not split Facebook and Instagram unless the file does.
  • OrganicInquiries with no paid campaign.
  • Offline / referralTours, referrals, and other inquiries that did not start on an ad.

Scope

Scope · proposed first version

FullStory shows the path from an ad to an enrolled student.

WhatConverts stays the lead-tracking foundation. FullStory connects those inquiries to school outcomes. It is not a CRM and it does not replace WhatConverts. FullStory is a provisional name for this preview.

Working in the sample

The sample dashboard is a preview with three views: Overview, Leads, and Data. Filters, charts, and the status list use built-in rows. Nothing is imported, nothing is matched to a real file, and nothing is sent to Google or Meta.

The sample chart counts inquiry, application, and enrolled. Accepted is not its own bar there. A lead counts on the inquiry date. An application or enrollment counts on the school status date. An older inquiry can sit behind an enrollment in a later window. The sample does not turn that pair into a conversion rate.

The sample timeline is the Leads view: a feed of arrival day, guardian contact, contact method, and marketing source. Qualified, unqualified, and unknown stay separate from inquiry, application, accepted, and enrolled. Methods in the file are form, call, and chat. It is not a WhatConverts timeline, a contact center, or the school’s admissions system.

Proposed first version

Not built. A first version would do the following. CSV export is the honest starting point. An API is not assumed to be available.

  1. Import leads from WhatConverts and school application and enrollment outcomes from CSV exports. A live API is not part of this version. What a real export contains has to be checked before the import is trusted.
  2. Match records with a confidence indicator. Uncertain and unmatched rows wait in a review queue. The product does not guess a confirmation.
  3. Show distinct stages: inquiry, application, accepted, and enrolled, using statuses the school confirmed.
  4. Report confirmed enrollments and cost per enrollment by channel, campaign, and campus when those fields are actually in the file.
  5. Flag missing data and CSV problems so an incomplete row is not presented as a trustworthy outcome.
  6. Show a basic timeline of when leads arrived, whether quality is qualified, unqualified, or unknown, and the later school status on its own date. Not a copy of another product’s timeline.
  7. Send school-confirmed outcomes (inquiry qualified, application, enrolled) back to Google Ads as offline conversions / enhanced conversions for leads (matched via GCLID and hashed email/phone, consent-aware). Meta Conversions API is a later phase.
  8. MVP path: CSV upload of enrollments, matched to attributed inquiries, then a scheduled upload to Google Ads. Later, the same outcomes can move automatically via FACTS (Heart) / Avela (CalOPS) sync, subject to API access verification.

How a school would use it

Bring in outcomes from a CSV, or add a lead by hand when a file is not available. Review uncertain matches. View results. Brandastic manages the technical setup.

Manual entry, beside the CSV

Not built. A school needs a way to record a lead when its software does not do that automatically. Manual entry sits next to the CSV import. It is not a second admissions system, and this page does not store a real student.

  1. Add a lead.
  2. Search for an existing inquiry and link to it, so the same family is not entered twice.
  3. Update application, accepted, or enrolled by hand. Enrolled stays a different status from an accepted offer.
  4. Record who made the change and when.
  5. Require a confirmation before an enrollment is treated as confirmed.
  6. Mark a source typed by a person as manually recorded. Mark a source that arrived from WhatConverts as tracked. If the source is not known, store Unknown. Do not invent one.

Later: automatic updates from the school platform

Planned. Subject to verified API access, permissions, and platform capabilities. This is not a supported integration and it is not live.

The aim is a secure connection the school authorizes, so application and enrollment outcomes can update without uploading the same CSV again. CSV import and manual entry stay available when a connection is not possible.

  • Show whether the connection is working.
  • Show the last successful update.
  • Show a failure in plain language, with a way to retry.

The first platforms to evaluate are FACTS for Heart and Avela for CalOPS. This page does not say those connections exist, or that either school has turned them on. If that access is verified, the sync can take the place of the CSV step in the Google Ads upload. Until then, the upload stays on the CSV path.

How often data would move, including whether that could ever be real-time or by webhook, is not decided until access is verified. Confirmed enrollment stays distinct from an accepted offer.

Not in this version

  • No live WhatConverts, FACTS, Avela, or CalOPS connection. FACTS stays the admissions record. Avela and CalOPS setup is unknown.
  • No Meta Conversions API in this version. That return is a later phase.
  • No ROI calculator. That stays in Google Sheets.
  • No student names or private records on this page.

A verified integration would be a later decision, after a CSV version shows whether the match is good enough. This page does not say that integration is ready.
